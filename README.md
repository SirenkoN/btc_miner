## Bitcoin-майнер (версия 0.63)

> Solo-майнер Bitcoin на Python, использующий только CPU. Полностью функционален (теоретически способен "найти блок"),
> но радикально медленнее чем asic решения. Проект пишется исключительно в учебных целях.

---

### 📦 Что есть

- **Solo-майнинг**  
  Получает шаблон блока через RPC, перебирает nonce и отправляет найденный блок.

- **Автообновление задания**  
  Обнаруживает появление нового блока в сети или изменение количества транзакций в шаблоне, перезапускает майнер с новым
  шаблоном.

- **Включение транзакций из mempool'а в заголовок блока**  
  Создает coinbase транзакцию из адреса пользователя, данных ноды о награде и комиссии.
  Строит merkle tree из транзакций mempool'а, расчитывает merkle root для правильного
  формирования заголовка блока.

- **Отправка полного блока ноде**  
  Ноде отправляется заголовок блока с nonce, а также список всех транзакций, на основе которых был создан заголовок.
  Это исключает случай когда в mempool ноды попали новые транзакции во время поиска nonce и найденный блок будет
  отклонен.

- **Параллельный майнинг на нескольких ядрах CPU**  
  Использует модуль multiprocessing для использования нескольких ядер процессора параллельно.

- **Использование модуля logging и цветовой схемы для разных типов сообщений**

  Добавлен мониторинг общего хешрейта системы в реальном времени с регулярным выводом статистики.

- **Рефакторинг отправки блока**  
  Отправка через submitblock теперь использует build_full_block для формирования полного блока.

#### Версия 0.4

- **Создание coinbase транзакции**  
  Реализовано создание coinbase транзакции из адреса пользователя и данных ноды.

- **Расчет merkle root**  
  Реализован расчет merkle root на основе coinbase транзакции и транзакций из mempool'а.

- **Оптимизировано количество RPC запросов к ноде**  
  Убрана часть запросов для оптимизации ресурсов.

- **Эффективное использование заголовка блока**  
  Заголовок блока собирается без nonce, для всего диапазона проверки nonce. Добавление
  nonce в заголовок происходит только перед хэшированием (существенно ускоряет работу
  майнера).

#### Версия 0.3

- **Автообновление задания**  
  Реализовано автоматическое обнаружение новых блоков в сети и обновление задания
  майнинга.

- **Корректная проверка условий майнинга**  
  Исправлено фундаментальное сравнение хеша с целевым значением: теперь используется
  `int.from_bytes(hash_val, 'little') < target_int` вместо некорректной реализации с
  `[:: -1]` и `'big'`.

- **Улучшенная обработка времени блока**  
  Время блока теперь корректно обрабатывается с учётом правил Bitcoin о допустимом
  отклонении (±2 часа от системного времени).

- **Эффективное кэширование шаблона**  
  Шаблон блока кэшируется и используется до тех пор, пока он не станет устаревшим,
  что снижает нагрузку на ноду.

- **Проверка высоты блока**  
  Добавлена проверка высоты блока для поиска обновлений шаблона.

- **Улучшенная обработка формата bits**  
  Переписана функция `target_from_bits` для корректной обработки всех случаев
  компактного представления целевого хеша согласно Bitcoin-протоколу.

#### Версия 0.2

- **Разделение на модули**  
  Исходный монолитный файл разделён на отдельные модули по принципу Single
  Responsibility (SRP):
    - `config.py` — конфигурация
    - `rpc_client.py` — взаимодействие с RPC-нодой
    - `utils.py` — утилиты хеширования и работы с целевыми значениями
    - `block_builder.py` — сборка заголовка блока
    - `main.py` — основная логика и точка входа

#### Версия 0.1

- **Базовая реализация**  
  Первоначальная версия майнера с минимальной функциональностью:
    - Получение шаблона блока через RPC
    - Перебор nonce
    - Отправка найденного блока

### 🚀 Как запустить

Внимание! Для запуска потребуется полностью синхронизированная локальная нода!

1. **Клонируйте репозиторий**

   ```bash
   git clone <URL>
   cd bitcoin-miner
   ```

2. **Установите зависимости**

   ```bash
   pip install requests bech32 base58
   ```

3. **Настройте RPC-параметры**

   Откройте файл `config.py` и заполните:

   ```python
   RPC_USER = "your_rpc_user"
   RPC_PASSWORD = "your_rpc_password"
   RPC_HOST = "127.0.0.1"  # Адрес ноды
   RPC_PORT = 8332  # Порт JSON-RPC
   ```

4. **Запустите скрипт**

   ```bash
   python3 main.py
   ```

### 🔧 Как работает

Шаг Описание
1. get_block_template() получает шаблон блока через RPC, включая версию, предыдущий хеш, транзакции из mempool и целевое
значение сложности (bits). Периодически проверяется на обновления с интервалом CHECK_INTERVAL.
2. Система создает WORKER_COUNT параллельных процессов, каждый из которых обрабатывает фиксированный диапазон
пространства nonce (равномерно разделенное пространство 0-2^32). Worker процессы получают заголовок блока (без nonce) и
целевое значение через разделяемую память. Для ускорения поиска заголовок блока собирается один раз на все диапазоны,
включая обработку времени блока с использованием медианного времени из шаблона (с коррекцией на допустимое отклонение ±2
часа).
3. При обнаружении подходящего nonce фоновый поток (result_checker_thread) проверяет его валидность, создает полный блок
через
build_full_block (включая coinbase транзакцию с вознаграждением на WALLET_ADDRESS и все транзакции из шаблона),
кэшированного в менеджере для этой задачи. Каждая задача идентифицируется уникальным идентификатором.
4. Полный блок отправляется через RPC методом submitblock, включая заголовок и все транзакции, что предотвращает
возможное отклонение из-за изменений в mempool ноды во время поиска nonce.
5. Система распределяет пространство nonce равномерно между WORKER_COUNT процессами. Каждый worker обрабатывает
NONCE_CHUNK_SIZE nonce за итерацию, начиная со случайной позиции в своем фиксированном диапазоне. Одновременно фоновый
поток собирает статистику хешрейта, вычисляя и отображая общее количество проверенных nonce в секунду (с автоматической
конвертацией в TH/s, GH/s, MH/s) каждые 5 секунд.
6. При обнаружении нового блока в сети (изменении высоты блока) система автоматически очищает кэш от устаревших
шаблонов (для заданий, чья высота блока меньше текущей на 2 и более), предотвращая использование неактуальных данных и
экономя память.

### ⚙️ Конфигурация

Все параметры находятся в файле `config.py`:

```python
# Конфигурация подключения к Bitcoin-ноде
RPC_USER = "your_rpc_user"
"""Имя пользователя для аутентификации в RPC"""
RPC_PASSWORD = "your_rpc_password"
"""Пароль для аутентификации в RPC"""
RPC_HOST = "127.0.0.1"
"""Хост Bitcoin-ноды (localhost по умолчанию)"""
RPC_PORT = 8332
"""Порт JSON-RPC (8332 по умолчанию для основной сети Bitcoin)"""

# Параметры майнера
WALLET_ADDRESS = "bc1qstf6dvdan9gfh2hzyqx73ttg6svukn0wytz7hr"
"""Адрес кошелька для получение вознаграждения за добытый блок"""
CHECK_INTERVAL = 1.0
"""Интервал проверки обновления шаблона блока в секундах"""
NONCE_CHUNK_SIZE = 1000000
"""Количество проверок nonce за одну итерацию (максимальный 32-битный nonce = 4294967295)"""
GPU_ENABLED = False
"""Флаг использования GPU (в текущей версии не поддерживается, функционал не реализован)"""
WORKER_COUNT = 12
"""Количество worker процессов для параллельного майнинга"""
```

- **`RPC_URL`** — параметры для установки соединения с Bitcoin-нодой через JSON-RPC.
- **`WALLET_ADDRESS`** — валидный Bitcoin-адрес (поддержка P2PKH, P2SH, Bech32).
- **`CHECK_INTERVAL`** — интервал проверки обновления шаблона блока майнером.
- **`NONCE_CHUNK_SIZE`** — размер чанка для поиска nonce (влияет на частоту пересборки шаблона и скорость реакции на
  новые блоки).
- **`GPU_ENABLED`** — параметр временно игнорируется (GPU-майнинг находится в разработке).
- **`WORKER_COUNT`** — количество параллельных процессов для майнинга (рекомендуется устанавливать равным числу
  логических ядер процессора).
